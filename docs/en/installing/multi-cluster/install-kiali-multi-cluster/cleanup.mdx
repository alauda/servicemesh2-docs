# Cleaning up Kiali

Remove Kiali from a multi-cluster mesh by unregistering the remote clusters first and deleting the Kiali server last. In the other order, the Kiali server is gone before the remote clusters are cleaned up, and their unused service accounts and roles stay behind.

## Prerequisites

- You have the cluster contexts of [Installing Kiali in a multi-cluster mesh](./index.mdx#prerequisites) available as `${CTX_CLUSTER1}` and `${CTX_CLUSTER2}`.

## Procedure

<Steps>
  ### Remove every remote cluster from Kiali

  Follow [Removing a cluster from Kiali](./index.mdx#removing-a-cluster-from-kiali) for the **West** cluster. This deletes the remote cluster secret on the **East** cluster and the Kiali resources on the **West** cluster, and leaves the Kiali server observing its own cluster only.

  Repeat it for every other remote cluster in the mesh.

  :::note
  The Kiali server is deleted in the next step, so you can skip the step that recreates its deployment.
  :::

  ### Delete the Kiali server on the **East** cluster

  Delete the `Kiali` resource by running the following command:

  ```bash
  kubectl --context "${CTX_CLUSTER1}" -n istio-system delete kiali kiali
  ```

  Confirm that the Operator removed the server:

  ```bash
  kubectl --context "${CTX_CLUSTER1}" -n istio-system get deployment kiali
  ```

  **Example output**

  ```text
  Error from server (NotFound): deployments.apps "kiali" not found
  ```
</Steps>

:::note
The Alauda Build of Kiali Operator stays installed on every cluster. To remove it and the Kiali custom resource definitions as well, see [Uninstalling Alauda Build of Kiali](../../../uninstalling/uninstalling-alauda-build-of-kiali.mdx).
:::
